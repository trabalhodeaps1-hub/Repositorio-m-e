### 3.MINIMUNDO<br>
Uma empresa necessita de um sistema para registrar e acompanhar problemas que ocorrem em qualquer setor. Atualmente, os funcionários comunicam os problemas de maneira manual, dificultando o controle das solicitações e o acompanhamento das soluções.
No novo sistema, qualquer funcionário poderá registrar um problema, informando a área da empresa onde ocorreu (como TI, Recursos Humanos, Financeiro, Produção ou Manutenção), uma descrição, a data e o nível de prioridade.
Após o registro, o problema será encaminhado para um supervisor ou colaborador encarregado de resolver a ocorrência. Esse responsável poderá atualizar o status do chamado (Aberto, Em andamento, Resolvido ou Cancelado), registrar observações sobre a solução adotada e informar a data de conclusão.
O funcionário que registrou o problema poderá acompanhar o andamento da solicitação e verificar quando ela for concluída. O sistema também permitirá consultar o histórico de problemas registrados, identificar quais áreas possuem maior quantidade de ocorrências e gerar relatórios para auxiliar a gestão da empresa.

#### 5.3 QUAIS PERGUNTAS PODEM SER RESPONDIDAS COM OS SISTEMA WEB/MOBILE PROPOSTOS?
    a) O sistema proposto poderá fornecer quais tipos de relatórios e informaçes? O sistema fornece relatórios dos responsáveis, das notas e de prioridade, contendo informações sobre quais são as pessoas que fizeram as solicitações, sua prioridade e o problema, nota de resolução, em quais equipamentos foram realizadas as atividades.

> O sistema de autorelatórios precisa inicialmente dos seguintes relatórios:
* Relatório que informe quais são os responsáveis por abrir cada inspeção e seus detalhes contendo as seguintes informações: id do usuário, id da inspeção, data e observações gerais.
* Relatório de nota de uma inspeção contendo: id da inspeção, id de relatório, data da inspeção, data do relatório, status do relatório.
* Relatório de problema da inspeção contendo: id do problema, título do problema, prioridade do problema, id da inspeção, data da inspeção, e observações gerais da inspeção.
* Relatório com os equipamentos inspencionado contendo: id do equipamento, id da inspeção, data da inspeção e observações gerais da inspeção.
* Relatório que mostre a qual área pertence cada equipamento contendo: id da área, id do equipamento, descrição da área e nome da área.

#### 7 Descrição dos dados 
    
  • INSPEÇÃO: Tabela que mostra as inspeções e seus solicitantes.
    • id_inspeção: id vinculado a uma inspeção (PK). <br>
    • id_usuario: id vinculado a um usuário (PK, FK). <br>
    • data: data de abertura da inspeção. <br>
    • obsevações_gerais: observações da inspeção. <br>
  
 • RELATORIO: Tabela de relatórios de inspeções.
   • id_relatorio: id vinculado ao relatório (PK). <br>
   • id_inspeção: id vinculado a uma inspeção (PK, FK). <br>
   • id_problema: id vinculado a um problema (PK, FK) <br>
   • status: status do relatório. <br>
   
 • PROBLEMA: Tabela de problemas de cada inspeção.
   • id_problema: id vinculado ao problema (PK). <br>
   • id_inspeção: id vinculado a uma inspeção (PK, FK). <br>
   • titulo: titulo do problema. <br>
   • prioridade: criticidade do problema. <br>

 • EQUIPAMENTOS: Tabela de equipamentos relacionados a cada inspeção.
   • id_equipamento: id vinculado ao equipamento (PK). <br>
   • id_inspeção: id vinculado a uma inspeção (PK, FK). <br>
   • data: data da inspeção. <br>
   • obsevações_gerais: observações da inspeção. <br>

 • AREA INDUSTRIAL: Tabela de áreas da empresa e seus equipamentos.
   • id_area: id vinculado a área (PK). <br>
   • id_equipamento: id vinculado ao equipamento (PK, FK). <br>
   • nome: nome da área. <br>
   • descrição: descrição da área. <br>

# Como Rodar o Código

### 1. Link do Repositório

Acesse o repositório do projeto AutoRelatório:

https://github.com/trabalhodeaps1-hub/Repositorio-m-e

### 2. Primeira forma: Baixar pelo GitHub (simples)

**Passo 1:** Acesse o link do repositório.

**Passo 2:** Clique no botão verde **Code**.

**Passo 3:** Selecione **Download ZIP**.

**Passo 4:** Após o download, extraia o arquivo ZIP para uma pasta do computador.

**Passo 5:** Abra o Visual Studio Code, clique em **Arquivo → Abrir Pasta** e selecione a pasta extraída do projeto.

### 3. Segunda forma: Baixar usando comandos no CMD

**Passo 1:** Abra o CMD do Windows. Pressione `Windows + R`, digite `cmd` e aperte Enter.

**Passo 2:** Acesse a pasta onde deseja salvar o projeto. Exemplo, para salvar em Downloads:

```cmd
cd %USERPROFILE%\Downloads
```

**Passo 3:** Digite o comando para baixar o repositório:

```cmd
git clone https://github.com/trabalhodeaps1-hub/Repositorio-m-e.git
```

**Passo 4:** Entre na pasta do projeto:

```cmd
cd Repositorio-m-e
```

**Passo 5:** Abra o projeto no Visual Studio Code:

```cmd
code .
```

**Observação:** Para utilizar a segunda forma, é necessário ter o Git instalado. O comando `code .` também exige que o comando do Visual Studio Code esteja configurado no sistema.
